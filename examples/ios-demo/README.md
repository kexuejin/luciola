# Luciola iOS Demo (SwiftUI + UniFFI Swift bindings)

Real Luciola engine on iOS via the uniffi **Swift** bindings. The supervision
primitives (stable identity, in-place restart, bind retry, idle tracking) live
in Rust, so this integration stays thin: NWPathMonitor drives `restart()`, a
small watchdog uses `secondsSinceIdle()`, and `isBound()` reflects whether the
discovery port was actually acquired.

## Layout

```
ios-demo/
├── LuciolaRadar/
│   ├── LuciolaRadarApp.swift      # entry point + @UIApplicationDelegateAdaptor
│   ├── ContentView.swift          # discovery list UI
│   ├── DiscoveryModel.swift       # engine + NWPathMonitor + watchdog
│   ├── BackgroundPresence.swift   # BGTaskScheduler + APNs hooks
│   └── Info.plist                 # generated by xcodegen from project.yml
├── project.yml                    # xcodegen project definition
└── README.md
```

The Rust side lives in `bindings/luciola-swift`:

```
bindings/luciola-swift/
├── luciola_uniffi.swift            # generated Swift bindings (uniffi-bindgen)
├── luciola_uniffiFFI.h/.modulemap  # C FFI header
└── LuciolaUniFFI.xcframework       # ios-arm64 + ios-arm64-simulator static libs
```

## Build & Run

Prereqs: Xcode, `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`,
[xcodegen](https://github.com/yonaskolb/XcodeGen).

```bash
# 1. Rust static libs (run from the repo root)
cargo build --release -p luciola-uniffi --target aarch64-apple-ios
cargo build --release -p luciola-uniffi --target aarch64-apple-ios-sim

# 2. Regenerate Swift bindings after changing the Rust API.
#    Ask cargo for the target directory — it is not always ./target.
TD=$(cargo metadata --format-version 1 --no-deps | sed -n 's/.*"target_directory":"\([^"]*\)".*/\1/p')
cargo run -p luciola-uniffi --bin uniffi-bindgen -- generate \
  --library "$TD/debug/libluciola_uniffi.dylib" \
  --language swift --out-dir /tmp/uo-sw
cp /tmp/uo-sw/luciola_uniffi.swift /tmp/uo-sw/luciola_uniffiFFI.h \
   /tmp/uo-sw/luciola_uniffiFFI.modulemap ../../bindings/luciola-swift/

# 3. Rebuild the xcframework (both slices + shared FFI headers)
./bindings/luciola-swift/build-xcframework.sh

# 4. Generate the Xcode project and build for the simulator
cd examples/ios-demo
xcodegen generate
xcodebuild -project LuciolaRadar.xcodeproj -scheme LuciolaRadar \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

Run on the same LAN as the desktop web console (`examples/web-radar-demo`) —
peers appear on both ends within seconds.

## Background presence — what iOS actually allows

**iOS presence is foreground-only plus opportunistic refresh.** There is no
foreground-service equivalent that can hold a UDP socket answering probes
indefinitely, so a suspended app will *not* answer `alive` probes. What is
wired here:

| Mechanism | What it buys | Cost |
| :-- | :-- | :-- |
| Foreground engine | full presence while the app is open | — |
| `BGAppRefreshTask` (`fetch`) | one opportunistic re-announce when iOS decides to run it, typically well under a minute | the system chooses if and when; not guaranteed |
| Silent APNs push (`remote-notification`) | wake a **suspended** app on demand to re-announce | needs a server to send the push and an APNs key |

`voip` and `audio` background modes would keep the socket alive, but both are
reserved for their real purpose and are rejected on review for anything else —
using them would trade a documented limitation for an App Store rejection, so
this demo does not.

`Info.plist` (generated by xcodegen from `project.yml`) declares
`UIBackgroundModes = [fetch, remote-notification]` and
`BGTaskSchedulerPermittedIdentifiers = [com.kapp.luciola.demo.LuciolaRadar.refresh]`.
That identifier **must** stay in sync with `BackgroundPresence.refreshTaskId`;
a mismatch makes `BGTaskScheduler.register` trap at launch.

`AppDelegate` registers the task handler before `didFinishLaunchingWithOptions`
returns (a requirement), always re-submits the next request before doing any
work (a task that forgets to reschedule breaks the chain permanently), and
stops the engine when the granted budget expires rather than being suspended
mid-write. A failed `registerForRemoteNotifications()` is logged, not fatal —
without an APNs entitlement it always fails and must not take the demo down.

The APNs device token is written to `UserDefaults` under `luciola.apns.token`
so a server can address the device.

**Verified in this environment** (2026-11-13): the app builds for the iPhone
17 Pro simulator against the freshly rebuilt `LuciolaUniFFI.xcframework`,
installs, and **launches**. Once running it reports `引擎在线`, which
`DiscoveryModel` sets from `session.isBound()` after a 2.5 s settle, so the
badge is a real bind result rather than an optimistic claim; the same screen
shows 7 candidate addresses and the subnet broadcast `192.168.2.255`, both
computed by the Rust core (`luciola-net`) inside the simulator process. The
process held `UDP *:17880` throughout. **Not** verified: peer discovery in the
simulator (broadcast frames from the Mac are not looped back — see the caveat
below, and two engines cannot share one host anyway because the discovery
socket binds exclusively), `BGAppRefreshTask` firing (the simulator does not
schedule background app refresh on demand — use the
`_simulateLaunchForTaskWithIdentifier` debugger trick on a device) and
silent-push delivery (needs a signed build with the `aps-environment`
entitlement plus a server holding the APNs key).

## Notes

- The demo binds the discovery port **17880** because the standard 17878 was
  occupied by a production peer node on the dev machine; change the `port:`
  argument in `ContentView.start(...)` if yours is free.
- **Simulator caveat**: the simulator shares the Mac's network stack, so
  LAN broadcast frames sent by the Mac are not looped back to it. Discovery
  between the simulator and the desktop works via the server's *unicast
  reconciliation* (peers already in the registry are dialed directly). Real
  devices discover each other through normal broadcast.
- Scanning the desktop QR code is not wired yet — use VisionKit
  (`DataScannerViewController`) or any QR scanner and feed the decoded
  `luciola://pair?...` URI into a Happy-Eyeballs dialer like the Android demo's.
